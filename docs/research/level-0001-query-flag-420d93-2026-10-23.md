## Observed

The code containing `0x00420d93` begins at `0x00420960` and returns with
`ret 0x1c`, consistent with seven stack arguments on this observed path. At
`0x00420d76`, it tests bit `0x02` in stack argument `[ebp+0x1c]`, loads the
seventh argument from `[ebp+0x20]`, and only takes the dynamic-flag call at
`0x00420d93` when both that bit is set and the seventh argument is nonzero.
Otherwise, the shown alternatives call the same query helper with literal `5`
or pass literal `0x11` to a different helper.

The dynamic flag is therefore not a newly computed value at `0x00420d93`: it
is the nonzero seventh argument of the enclosing `0x00420960` path. The direct
calls found by the bounded whole-image scan show these seventh-argument
provenances:

| Direct call to `0x00420960` | observed seventh argument |
| --- | --- |
| `0x00403989` | literal `0` |
| `0x00420df3` | caller's `[ebp+0x20]` forwarded unchanged |
| `0x004219a8` | literal `0` |
| `0x004219c9` | literal `0` |
| `0x0042868f` | literal `0` |
| `0x0044ca10` | value loaded from that caller's stack `[esp+0x10]` |

Thus the immediately visible zero-valued direct calls cannot reach the
nonzero dynamic-flag branch as written. The `0x00420df3` recursive forwarding
and `0x0044ca10` stack-derived source remain unresolved without tracing their
callers and branch feasibility.

Bounded follow-ups establish that neither edge synthesizes a value: the
recursive edge forwards its seventh argument unchanged, while the `0x0044c9f0`
wrapper forwards its fourth argument unchanged as that seventh argument and
has no direct relative CALL in the whole-image scan. See
[the recursive trace](level-0001-query-flag-420df3-2026-10-23.md) and
[the wrapper trace](level-0001-query-flag-44ca10-2026-10-23.md).
